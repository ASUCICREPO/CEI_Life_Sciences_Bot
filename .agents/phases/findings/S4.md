# S4 — HITL spike findings

Status: **not proven in AgentCore**. The isolated experiment in
`backend/agents/spikes/hitl_spike` creates the existing typed choice surface,
interrupts, and reconstructs the pending surface from the graph checkpoint on a
new graph instance. A local in-memory test verifies resumption, stale revision,
invalid choice and duplicate action rejection. It does not prove process-level
durability, atomic concurrent action handling, the production endpoint, or SSE.

The harness can run start and resume in separate Python processes against an
existing AgentCore Memory ID, actor ID and thread ID. `DurableSpikeStack` also
defines an isolated IAM-authenticated runtime for the same experiment. A deployed runtime and live
memory test remain outstanding; deployment must use the CEI CodeBuild path rather
than a CLI deployment. Record timestamps, session
and checkpoint references, and outputs after the wait and new-run resume.

AWS documents that memory event retention has a maximum of 365 days
([Memory API](https://docs.aws.amazon.com/bedrock-agentcore-control/latest/APIReference/API_Memory.html)).
This supports B82's expiry behavior but does not independently prove the
checkpoint's lifetime or an expired-checkpoint response in the application.
