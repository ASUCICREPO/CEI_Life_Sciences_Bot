# S3 — Async spike findings

Status: **not proven in AgentCore**. The isolated spike graph and async entrypoint
are under `backend/agents/spikes/async_spike`. Local tests exercise cancellation
between checkpointed steps and resumption after an injected exception with an
in-memory checkpointer. Those tests do not establish distributed durability.

The isolated `DurableSpikeStack` defines an IAM-authenticated runtime, memory,
and cancellation table when the `durable` spike context is selected. It has not
been deployed. The `cei-project` profile
has a CEI CodeBuild project in `us-east-1`; the user has specified that deployments
must not be performed from the CLI. The following remain untested: a real run longer than one hour,
HealthyBusy, both cancellation methods, AgentCore Memory recovery, token expiry,
and redeployment during a run. F16 must not treat those requirements as proven.

For a future isolated deployment, use the stack's dedicated AgentCore memory and
DynamoDB table, then invoke the runtime with unique `job_id`, `actor_id`
and `thread_id`. An item with `cancel_requested=true` requests cooperative
cancellation; the runtime emits the final completed-step count in its log. Use
66 steps with 60 seconds each for an actual run past one hour. Kill and resume
with the same identifiers and `resume=true`; capture runtime session IDs,
timestamps, checkpoint observations and exact outcomes for every scenario.

AWS documents a 365-day maximum memory event expiry, but this does not prove
checkpoint behavior under redeployment or expiration. See the [Memory API](https://docs.aws.amazon.com/bedrock-agentcore-control/latest/APIReference/API_Memory.html).
